# AXIS ONE COFFEE - Product Blueprint v2.0
*"Del ERP al Ecosistema de Herramientas"*

## 1. Visión

Axis One Coffee deja de ser un ERP que intenta resolver todos los problemas del café desde el primer contacto.

Se convierte en un ecosistema de herramientas especializadas, independientes y conectadas, donde cada herramienta resuelve un problema puntual y puede ser utilizada sin necesidad de adoptar el sistema completo.

El objetivo no es vender un software.

El objetivo es convertirse en la caja de herramientas digital de la industria del café.

## 2. Filosofía

- No vender un ERP.
- No obligar al usuario a aprender un sistema complejo.
- No exigir registros innecesarios.
- No pedir información que el usuario todavía no entiende por qué debe entregar.
- Primero resolver.
- Después capturar datos.
- Finalmente conectar todo el ecosistema.

## 3. Objetivo Estratégico

Construir el ecosistema de herramientas digitales más completo para la industria del café.

Cada herramienta debe:
- resolver un problema específico;
- ser útil por sí sola;
- compartir usuarios y datos con Axis One;
- servir como puerta de entrada al ecosistema.

## 4. Nuevo Modelo Comercial

**Antes:**
Cliente ↓ Demo ↓ ERP ↓ Uso

**Ahora:**
Cliente ↓ Herramienta ↓ Confianza ↓ Más herramientas ↓ Suscripción ↓ Axis One Completo

## 5. Principios del Producto

**Una herramienta = un problema**
Nunca intentar resolver varios problemas en una misma interfaz.

**Menos formularios**
Solo solicitar la información indispensable.

**Misma experiencia visual**
Todas las herramientas compartirán:
- identidad gráfica;
- componentes;
- navegación;
- lenguaje;
- experiencia de usuario.
El usuario debe sentir que siempre está dentro de Axis One.

**Una sola cuenta**
- Un único usuario.
- Un único inicio de sesión.
- Una única base de datos.

**Datos compartidos**
Toda información registrada podrá ser reutilizada por cualquier herramienta del ecosistema.

## 6. Objetivo oculto

Construir la mayor base técnica de conocimiento del café.

Cada herramienta captura información diferente. Cuando toda esa información se conecta aparece la verdadera ventaja competitiva:

**La Banca Técnica del Café.**

## 8. Modelo Freemium

Todas las herramientas tendrán tres niveles.

**Gratuito**
- Resolver el problema.

**Cuenta gratuita**
- Guardar información.
- Historial.
- Sincronización.

**Premium**
- Reportes.
- PDF.
- QR.
- Criptografía.
- Exportaciones.
- Automatización.

## 10. Principios de Desarrollo (para Antigravity)

Cada nueva herramienta debe cumplir estas reglas:
- No duplicar código existente.
- Reutilizar componentes de Axis One.
- Mantener el diseño visual.
- Compartir autenticación.
- Compartir base de datos.
- Poder funcionar de forma independiente.
- Mantener compatibilidad con el ecosistema.
- Registrar eventos para analítica.
- Ser optimizada para dispositivos móviles.

## 11. Métrica de Éxito

No medir el éxito únicamente por ventas. También medir:
- herramientas utilizadas;
- usuarios registrados;
- datos capturados;
- tiempo de uso;
- herramientas más usadas;
- conversión entre herramientas;
- conversión hacia la suscripción completa.

## 12. Nuestra Promesa

No construimos un ERP para el café. Construimos las herramientas que los profesionales del café necesitan cada día. Cuando esas herramientas trabajan juntas, aparece el ecosistema Axis One Coffee.

## 13. Reglas de decisión (Constitución de Axis One Toolbox)

Este capítulo sirve para decidir si una idea entra o no entra en el ecosistema. Cada decisión futura —de desarrollo, marketing o producto— debe contrastarse contra estas reglas para verificar si sigue alineada con la visión del ecosistema.

- Si una herramienta no resuelve un problema claro en menos de cinco minutos, no se desarrolla.
- Si requiere explicar el ERP completo para entenderla, debe simplificarse.
- Si no aporta valor por sí sola, permanece dentro de Axis One y no se extrae.
- Si captura datos útiles para enriquecer el ecosistema y además resuelve un problema real, es candidata a convertirse en una herramienta independiente.
- Si una funcionalidad puede atraer nuevos usuarios al ecosistema con poca fricción, tiene prioridad sobre funcionalidades que solo benefician a usuarios avanzados.
